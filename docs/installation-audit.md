Inspected 2026-10-26. Investigation only; desktop configuration and packages were not changed.

The installed source is `https://github.com/caelestia-dots/caelestia.git`, not the user's fork. The fork at https://github.com/opx0/caelestia contains app dotfiles; the shell is a separate project.

Installed versions: caelestia-shell 2.5.0-1, caelestia-cli 1.1.3-1, Hyprland 0.56.2-4, quickshell-git 0.3.1.r10.g2d3b3e9-1. `hyprctl plugin list` reports no loaded compositor plugins. This does not establish the presence or absence of application extensions.

## Update behavior

The installed CLI reads `dots.url` and `dots.branch` from `cli.json`, defaulting to upstream main. Its `utils/dots/source.py` deletes and reclones the cache if the configured URL changes. It also has hard-reset and untracked-clean operations. Preserve local work outside that cache before changing sources.

`caelestia update` includes a system/package update and dotfile deployment. It is broader than refreshing just the panel. Personal Hyprland changes belong in the override files. Existing `cli.json` enables GTK/Qt theming and a Dolphin synchronization hook; preserve these keys when extending the config.

## Horizontal bar findings

The installed `modules/bar/Bar.qml` uses `ColumnLayout`. `BarWrapper.qml` sizes and animates width. `modules/drawers/Exclusions.qml` reserves the left edge. `Regions.qml` and `ContentWindow.qml` offset panels using bar width. Bar hover and popup lookup use y coordinates.

A horizontal bar therefore requires coordinated changes to layout, wrappers, exclusive zones, border geometry, workspace/clock/title presentation, popup anchors, hover regions and scroll behavior. A JSON-only orientation change is not supported by the inspected implementation.

## Proposed implementation order

1. Put personal Caelestia overrides and hooks under the existing `~/dotfiles` workflow. Back up and compare before replacing live files with symlinks. Exclude caches, history, generated theme outputs and recordings.
2. Keep a separate development checkout for `opx0/caelestia`; use it only for intentional changes to deployed upstream defaults. Select it through CLI configuration after preserving the cache and validating the fork revision.
3. Create a separate shell development checkout based on the installed shell version. Develop horizontal layout there, leaving package-owned files intact. Activate through a reversible user-level shell path only after verification.
4. Use a top horizontal bar as the initial design assumption. Check workspace switching, clock, tray, audio/network/battery popouts, dashboard, launcher, notification panels, fullscreen and multiple monitors.
5. Audit plugin categories separately: compositor plugins, shell widgets/modules, and app extensions. Choose upgrades based on requested behavior and compatibility with installed versions.
